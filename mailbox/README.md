# Mailbox

跨 commit 的功能開發記錄。單一 commit message 只交代那次改動本身；這裡記錄一個功能／一次協作在完成前後的完整脈絡——目的、拆分邏輯、測試方式與結果、留下的待辦——方便之後回頭查，不用逐一翻 commit。

對應 `CLAUDE.md` 功能開發分支流程第 2 點：「完整開發並留下記錄：開發內容記錄、目的、測試方式與結果記錄（寫入 commit / mailbox thread / docs）」。

## 使用方式

- 一個 thread 一個檔案：`YYYY-MM-DD_<slug>.md`，`slug` 用 kebab-case 簡述主題。
- 每篇 thread 建議包含：
  - **Context**：為什麼要做這件事、從哪裡發現的
  - **開發內容**：做了什麼，對應哪些 commit（列 commit hash + 一行描述）
  - **測試方式與結果**：怎麼驗證的，結果如何（含失敗/跳過的部分，不要只寫「測試通過」）
  - **待辦 / 已知落差**：這次沒處理、但值得之後回頭看的事
- 只在功能**完整完成**時寫，不用逐步更新；跟 commit message 一樣禁止 emoji、圖示。
